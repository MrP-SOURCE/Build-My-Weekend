# BUILD MY WEEKEND — FREE MVP

Build a working mobile-first web application called **BUILD MY WEEKEND**.

## PURPOSE

Prove this core idea:

> **“I have R3,000. Where can I realistically go for the weekend?”**

The user enters their budget, group size, desired experience, driving limit and vehicle information. The app calculates realistic weekend options and shows what the trip will cost and how much money remains.

This is an **evaluation MVP**, not a production tourism platform.

Build ONLY the MVP.

* paid APIs
* external APIs
* databases
* login/accounts
* payments
* booking integrations
* subscriptions
* AI services
* complex backend
* unnecessary features

Use demonstration data stored directly in JavaScript.

Clearly label all destination, accommodation, food, activity, fuel and practical information as:

**DEMONSTRATION DATA — NOT LIVE**

## VEHICLE CALCULATION

Keep these two concepts separate:

**FUEL CONSUMED**

and

**ADDITIONAL FUEL PURCHASE REQUIRED**

Formula:

```text
return distance = one-way distance × 2

litres consumed =
return distance × consumption / 100

fuel consumed =
litres consumed × fuel price

additional fuel purchase =
max(0, fuel consumed - fuel already in vehicle)

total trip spend =
additional fuel purchase
+ accommodation
+ food
+ activities

money remaining =
budget - total trip spend

cost per person =
total trip spend / people
```

Fuel already in the vehicle must NOT be deducted from the budget.

It is fuel the user already owns.

## RESULTS

After calculation show:

# YOUR WEEKEND OPTIONS

Display up to three different recommendation cards:

### CLOSEST AFFORDABLE

### BEST VALUE

### FURTHEST AFFORDABLE

Each card shows:

* destination
* distance
* drive time
* estimated additional fuel purchase
* total estimated spend
* money remaining
* activities
* practical information
* `VIEW WEEKEND`

Recommendation logic:

**Closest:** shortest distance.

**Best value:** greatest money remaining, then shortest distance.

**Furthest:** greatest distance.

Never show an unaffordable destination as affordable.

If fewer than three destinations qualify, show the available ones.

If none qualify, explain clearly why.
